Non-technical fitness review#

This is historical acceptance evidence from the original audit, not the current user guide. The product has changed since the verdict; use Quickstart and Studio tour for current instructions.

Verdict at review time: rhobuilder was a strong, honest developer/CI engine and a weak non-technical product. The technical gate was roughly 7.5/10; the one-stop-shop experience was roughly 2.5/10 until the UI, readiness and packaging work landed.

Each finding has a disposition and a traceability row to the UI or CLI change that addresses it.

What is genuinely strong#

  • Mainnet is refused before HTTP; testnet live actions require --allow-live plus an identity+plan confirmation token.
  • Keys stay mode 0600, gitignored and unprinted; devnet-named keys are refused on live networks.
  • Adopt-before-deploy and a partial-root stop prevent duplicate primitives.
  • not_run is a first-class result; a throttled devnet never reads as a pass.
  • P5 is measured: five devnet roots, a generated app, and nine behavioural suites.

Boundary#

The UI may read, plan, validate, start conversations and save a validated design.json. It must not write code, apply a scaffold, sign, fund, hold keys or execute deploys. Those operations remain CLI-only with explicit gates.
